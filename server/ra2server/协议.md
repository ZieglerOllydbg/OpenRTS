# RA2 游戏服务器通信协议

## 1. 概述

本文档描述了 RA2 游戏客户端与服务器之间的 WebSocket 通信协议。所有消息均使用 JSON 格式进行传输。

## 2. 消息格式

所有消息都遵循以下基本格式：

```json
{
  "type": "消息类型",
  "data": { /* 消息数据 */ }
}
```

其中：
- `type`: 字符串，表示消息类型
- `data`: 对象，包含具体的消息数据

## 3. 客户端到服务器的消息

### 3.1 匹配请求

客户端发送匹配请求，加入游戏匹配队列。

**消息格式：**
```json
{
  "type": "match",
  "data": {
    "name": "玩家名称",
    "roomType": "房间类型"  // 可选值: SOLO, DUO, TRIO, QUAD, OCTO
  }
}
```

**字段说明：**
- `name`: 玩家名称
- `roomType`: 房间类型（可选），默认为 DUO

### 3.2 准备就绪

玩家在房间中准备就绪。

**消息格式：**
```json
{
  "type": "ready"
}
```

### 3.3 取消匹配

玩家在匹配等待阶段主动取消匹配。已经进入房间后不能使用该消息取消匹配，应使用 `leave` 离开房间。

**消息格式：**
```json
{
  "type": "cancelMatch"
}
```

### 3.4 帧输入数据

玩家发送游戏输入数据。

**消息格式：**
```json
{
  "type": "frameInput",
  "frame": 10,
  "data": [
    // 输入数据数组
  ]
}
```

**字段说明：**
- `frame`: 帧编号
- `data`: 输入数据数组

### 3.5 离开房间

玩家主动离开房间。

**消息格式：**
```json
{
  "type": "leave"
}
```

### 3.6 Ping消息

客户端发送ping消息检测连接状态。

**消息格式：**
```json
{
  "type": "ping"
}
```

### 3.7 重连房间

玩家断线后使用匹配成功时返回的房间ID和玩家Token重新绑定房间身份。

**消息格式：**
```json
{
  "type": "reconnect",
  "data": {
    "roomId": "房间ID",
    "token": "玩家Token",
    "lastFrame": 120
  }
}
```

**字段说明：**
- `roomId`: 匹配成功时返回的房间ID
- `token`: 匹配成功时返回的玩家Token
- `lastFrame`: 客户端已处理的最后帧，缺省时服务器从第0帧开始补发

### 3.8 获取历史帧文件

客户端按文件名请求服务器已持久化的历史帧文件。该请求不需要房间ID，服务器会按文件名读取 `data/history-frames` 目录下的JSON文件。

**消息格式：**
```json
{
  "type": "getHistoryFrames",
  "data": {
    "fileName": "history_frames_2_1714280000000_123456789.json"
  }
}
```

**字段说明：**
- `fileName`: 历史帧文件名，只允许基础JSON文件名，不能包含路径分隔符

## 4. 服务器到客户端的消息

### 4.1 匹配确认

服务器确认收到匹配请求。

**消息格式：**
```json
{
  "type": "matched"
}
```

### 4.2 匹配成功

匹配成功，进入房间。

**消息格式：**
```json
{
  "type": "matchSuccess",
  "roomId": "房间ID",
  "yourCampId": 1,
  "yourToken": "玩家Token",
  "data": [
    {
      "campId": 1,
      "name": "玩家1"
    },
    {
      "campId": 2,
      "name": "玩家2"
    }
  ]
}
```

**字段说明：**
- `roomId`: 房间ID
- `yourCampId`: 自己的阵营ID
- `yourToken`: 玩家Token
- `data`: 房间内所有玩家信息列表

### 4.3 取消匹配结果

服务器返回玩家主动取消匹配的处理结果。

**消息格式：**
```json
{
  "type": "matchCancelled",
  "success": true
}
```

取消失败时会返回失败原因：

```json
{
  "type": "matchCancelled",
  "success": false,
  "reason": "not_matching"
}
```

**字段说明：**
- `success`: 是否取消匹配成功
- `reason`: 取消失败原因，可选值包括 `not_matching`、`already_in_room`

### 4.4 游戏开始

所有玩家准备就绪，游戏开始。

**消息格式：**
```json
{
  "type": "gameStart",
  "fileName": "history_frames_2_1714280000000_123456789.json"
}
```

**字段说明：**
- `fileName`: 本局历史帧持久化文件名。服务器在发送 `gameStart` 时创建该文件名，房间销毁时使用同一文件名写入 `data/history-frames` 目录。

### 4.5 帧同步数据

服务器广播的帧同步数据。

**消息格式：**
```json
{
  "type": "frameSync",
  "frame": 10,
  "data": [
    {
      "campId": 1,
      "inputs": [
        // 玩家输入数据
      ]
    }
  ]
}
```

**字段说明：**
- `frame`: 帧编号
- `data`: 所有玩家的输入数据

### 4.6 Pong消息

服务器对客户端ping消息的响应。

**消息格式：**
```json
{
  "type": "pong"
}
```

### 4.7 重连成功

玩家身份校验成功，服务器已经将新连接绑定到原房间玩家。

**消息格式：**
```json
{
  "type": "reconnectSuccess",
  "roomId": "房间ID",
  "yourCampId": 1,
  "currentFrame": 150
}
```

**字段说明：**
- `roomId`: 房间ID
- `yourCampId`: 重连玩家的阵营ID
- `currentFrame`: 服务器当前房间帧号

重连成功消息发送后，服务器会按帧号顺序补发客户端 `lastFrame` 之后保存的所有 `frameSync` 消息。

### 4.8 重连失败

玩家重连请求未通过校验或房间不可用。

**消息格式：**
```json
{
  "type": "reconnectFailed",
  "reason": "room_not_found"
}
```

**字段说明：**
- `reason`: 失败原因，可选值包括 `room_not_found`、`token_invalid`、`room_destroyed`

### 4.9 历史帧文件获取成功

服务器成功读取历史帧文件后，先返回历史帧文件元数据，再按批次返回历史帧列表。服务端会缓存成功读取结果，同一文件在缓存有效期内重复请求会直接使用缓存拆分回发。

**开始消息格式：**
```json
{
  "type": "historyFramesStart",
  "fileName": "history_frames_2_1714280000000_123456789.json",
  "data": {
    "fileName": "history_frames_2_1714280000000_123456789.json",
    "roomId": "room_1",
    "playerCount": 2,
    "players": []
  },
  "isEnd": false
}
```

**帧批次消息格式：**
```json
{
  "type": "historyFramesFrame",
  "fileName": "history_frames_2_1714280000000_123456789.json",
  "frames": [
    {
      "frame": 1,
      "message": "{\"type\":\"frameSync\",\"frame\":1,\"data\":[]}"
    }
  ],
  "isEnd": true
}
```

**字段说明：**
- `fileName`: 请求的历史帧文件名
- `data`: 历史帧文件中的非帧元数据，不包含 `frames` 字段
- `frames`: 当前批次的历史帧数组，每个 `historyFramesFrame` 最多包含10帧
- `isEnd`: 当前消息是否为本次历史帧回发的最后一个消息；无历史帧时，`historyFramesStart` 会直接返回 `true`

### 4.10 历史帧文件获取失败

服务器无法读取历史帧文件时返回失败原因。文件不存在也会短期缓存，避免客户端重复请求时频繁访问磁盘。

**消息格式：**
```json
{
  "type": "historyFramesFailed",
  "fileName": "history_frames_2_1714280000000_123456789.json",
  "reason": "file_not_found"
}
```

**字段说明：**
- `fileName`: 请求的历史帧文件名，文件名非法且无法解析时可能不存在
- `reason`: 失败原因，可选值包括 `invalid_file_name`、`file_not_found`、`read_failed`、`service_shutdown`

## 5. 房间类型

支持以下房间类型：

| 类型  | 玩家数量 |
|-------|----------|
| SOLO  | 1        |
| DUO   | 2        |
| TRIO  | 3        |
| QUAD  | 4        |
| OCTO  | 8        |

## 6. 阵营ID

不同数量玩家的房间会分配不同的阵营ID：

- 1人房间：Red(1)
- 2人房间：Red(1), Blue(2)
- 3人房间：Red(1), Blue(2), Green(3)
- 4人房间：Red(1), Blue(2), Green(3), Yellow(4)
- 8人房间：Red(1), Blue(2), Green(3), Yellow(4), Orange(5), Purple(6), Pink(7), Brown(8)
